# Finance CLI App Agent Guide

## Project Shape

- `src/cfo_platform/` is the FastAPI CFO Platform. Keep routes under `/api/v1`; use the application ports, infrastructure adapters, and `composition.py` container rather than coupling routes directly to implementations.
- `src/finance_cli/` is the Typer-based quantitative CLI. Preserve deterministic simulation behavior and explicit random seeds.
- `frontend/` is the React/Vite CFO Command Center. It is an active application even though the root README has outdated frontend status text.
- `tests/` contains backend tests, commonly organized by implementation epic. Frontend unit tests live with source and end-to-end tests live in `frontend/tests/e2e/`.

## Backend Workflow

From the repository root, install development dependencies with `uv sync --locked --extra dev`.

- Run a focused backend test with `uv run pytest tests/test_<area>.py` before broader checks.
- Run all backend tests with `uv run pytest`; run linting with `uv run ruff check .`; run strict typing with `uv run mypy`.
- Start the API with `uv run cfo-api` or `uv run uvicorn cfo_platform.api.main:app --reload`.
- For API behavior, use the FastAPI app factory and `build_container()` test pattern rather than module-level mutable application state.

## Frontend Workflow

From `frontend/`, use Node.js 22+ and npm 10+.

- Run `npm run lint`, `npm run typecheck`, `npm run test`, and `npm run build` for a frontend change. Use `npm run test:e2e` when the user flow is affected.
- After changing a FastAPI route or Pydantic request/response model consumed by the frontend, run `npm run api:sync` before frontend validation.
- Never hand-edit `frontend/src/api/generated/schema.d.ts`; it is generated by the API synchronization step.
- Use `VITE_API_MODE=mock npm run dev` only for frontend-only work. MSW fixtures must match the generated contract.

## Cross-Component Rules

- The backend owns finance calculations, authoritative validation, authorization, workflows, and persisted state. The frontend owns presentation, interaction state, formatting, visualization, and accessible loading/empty/error states.
- Do not recreate finance, risk, or simulation calculations in the browser. Do not invent unavailable frontend read models, identity headers, or company/period/scenario data; retain explicit mock/local-context labeling until a backend contract exists.
- Treat the FastAPI OpenAPI schema as the machine-readable frontend/backend contract. Keep generated types, API adapters, MSW handlers, and feature queries aligned.
- Preserve governance, audit, company scope, and model/run lineage whenever changing a backend domain workflow.
